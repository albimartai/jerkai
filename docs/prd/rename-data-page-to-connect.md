## 2. Problem statement

`/data` (`app/data/page.tsx`) is the correct feature under the wrong name for what Albert wants it called going forward — and the legacy `/status` path still reaches it through an indirection (previously one hop, now needing correction to skip the freed `/data` path entirely) that is worth tightening while the route is already being touched. Nothing about what the page does or how it looks needs to change; the route, the `NavHeader` label, both legacy redirect targets, and the file paths/identifiers/test descriptions that encode the label all do.

## 3. Objective

A signed-in user visiting the page previously reachable at `/data` now reaches it at `/connect`, and the header's resolution-adjacent link reads "Connect." A user who requests either legacy path (`/status` or `/data`) lands on `/connect` after exactly one redirect. Every card, category, Connect action, and sync-history line renders exactly as it does today, and every existing test's descriptive name accurately reflects which route it now covers. Success = a single testable condition: a signed-in user's browser, on `NavHeader`, shows a link reading exactly "Connect" whose `href` is exactly `/connect`; requesting `/data` or `/status` each redirects there in one hop.
